# Personal dotfiles

Managed with Waysync. Environment and device are separate choices; there are no
machine-specific branches.

## Layout

- `manifest.toml`: environments and an explicit ordered list of component files.
- `components/*.toml`: modules grouped by desktop, system, login, terminal,
  theming, gaming, file management, apps, development, and Cortana.
- `dotfiles/`: shared configuration and safe shell/plugin fallbacks.
- `overrides/<environment>/`: shell-specific files, startup services, and bindings.
- `devices/desktop/dotfiles/` and `devices/laptop/dotfiles/`: monitor rules and
  workspace monitor priority. The existing resolutions/positions are preserved.
- `packages/`: maintained local PKGBUILDs, including their actual package dependencies.
- `scripts/waysync/`: deployment helpers; these run only when their hook is invoked.

## Workflow

```bash
waysync check --repo ~/Projects/dotfiles --all
waysync update
waysync device laptop          # Or desktop; keeps the environment
waysync sync                   # Restore missing packages and apply selected components
waysync deploy --no-hooks      # Strictly dotfiles; no package checks or hooks
waysync capture --repo ~/Projects/dotfiles --dry-run
waysync capture --repo ~/Projects/dotfiles
```

Capture applies only to components with `ask = true`; it remembers this checkout,
reviews local edits, preserves override routing, and never commits or pushes.
Component names and existing default selections remain stable across the layout change.

## Dependencies and optional features

Use `packages` for software chosen by this configuration, optional integrations,
and helpers used by custom scripts. Ordinary runtime/build dependencies belong
in the package's `depends`/`makedepends`, not a duplicate `requirements` array.
Pacman resolves those relationships. Explicitly listing the same helper in two
modules is fine: removing one module preserves claims from the other.

Waysync additionally preserves packages required by installed software, including
software outside Waysync. Removal never cascades or recursively purges dependencies.
A saved package removed outside Waysync is restored on the next component sync.

`greetd` and `sddm` are optional login-manager choices: select one. Their activation
runs on first installation; ordinary deployment reloads configuration without
re-enabling a different manager on every sync.

DMS settings are generated by DMS in `~/.config/DankMaterialShell`; no nonexistent
`dms/` directory is deployed. DMS and Noctalia v5 have working shell service and
basic launcher/lock bindings. Their remaining preferences are app-managed until
explicit configuration files are added here. Optional Hyprland plugins have native
workspace fallbacks, so disabling the plugin module does not prevent keybindings
from loading. No plugin cache purge or package update runs on ordinary Hyprland deploys.

Service/IPC references: [Noctalia v5](https://docs.noctalia.dev/noctalia/getting-started/running-the-shell/)
and [DMS](https://github.com/AvengeMedia/DankMaterialShell).
